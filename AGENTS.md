# AGENTS.md — Yatim Mandiri OmatiQ

## Stack

Laravel 13 + Inertia v3 + React 19 SPA. TypeScript 6, Tailwind v4, Vite 8.

Key packages: Fortify (auth), Socialite, Reverb (websockets), Spatie (permissions, media-library, settings, activitylog, backup), Firebase, DomPDF, TipTap (rich text), Wayfinder (TS route helpers), Pest 4 (tests), google/apiclient (Sheets).

## Architecture

- **Auth**: Fortify handles login/register/reset-password/2FA/email-verification (for `Administrators`/`Participant`/`Cabang`). Guru login is **phone + local password via Penyaluran identity** (`GuruAuthController@store` validates `phone` + `password` -> phone normalization `08`/`628`/`8` variants -> `POST api/v1/guru/login` `{phone}` -> Bearer token -> `GET guru/me` -> `User::firstOrCreate(penyaluran_id)` with local placeholder email `guru{id}@penyaluran.local`, synced `penyaluran_token`/`phone`/`Teacher` role, and default first password `password` until admin-provided/reset). After successful password check, first-time/incomplete teachers are forced to `GET teacher/complete-profile` (`auth/guru-complete-profile.tsx`) via `User::needsTeacherProfileCompletion()` (`Teacher` role + `teacher_profile_completed_at` null + placeholder email), then `PUT teacher/complete-profile` validates `email` (unique, lowercase) + `password` (`Password::min(8)` explicit, global `Password::defaults()` = `Password::min(8)` always via `AppServiceProvider` production+local) → `PenyaluranService::updateMe(token)` `PUT api/v1/guru/me` `{email}` Bearer (timeout 8, retry 2, `Cache::forget penyaluran:me:`.sha1(token)) — if API fails local DB is **not** updated and `withErrors('email')` is returned (best practice: token missing → `Sesi Penyaluran tidak ditemukan`); on success it stores real unique email, hashes new password, sets `email_verified_at` + `teacher_profile_completed_at`, and redirects to `teacher.dashboard`; completed teachers skip this form on future logins. `EnsureTeacherProfileCompleted` middleware protects admin/settings areas from bypassing the required profile completion page. Direct `Auth::login` is used when `PENYALURAN_OTP_ENABLED=false` (default, `config/services.php:penyaluran.otp_enabled`). `FortifyServiceProvider` binds `LoginResponse` and `LogoutResponse` role-aware (`Teacher` → `teacher.dashboard` / `teacher.login`, `Participant` → `student.dashboard` / `login`, `Administrators`/`Cabang` → `admin.dashboard` / `admin.login`). `bootstrap/app.php` `Authenticate::redirectUsing` stores `url.intended` for `admin/*` → `login` vs `teacher/*` → `teacher.login` so `redirect()->intended` resumes last page, not `/`. `AuthController@loginStore` fallback `intended(admin.dashboard)` not `/`. **OTP scaffold** (`app/Services/PhoneOtpService.php`, hashed 6-digit `phone_otp` + `phone_otp_expires_at` 5min / `phone_otp_attempts` 5 / lockout 15min / resend cooldown 60s, `users.phone_otp*` + `phone_verified_at` columns) when `PENYALURAN_OTP_ENABLED=true`: `generate()` -> `session otp_user_id` -> `GET teacher/verify-otp` (`GuruAuthController@showOtpForm`, `auth/guru-verify-otp.tsx`) -> `POST teacher/verify-otp` -> `POST teacher/resend-otp`; routes under `guest` + throttles `5,1`/`3,1` in `routes/auth.php` (`teacher.login`, `teacher.login.store`, `teacher.verify`, `teacher.verify.store`, `teacher.resend`, `teacher.profile.edit`, `teacher.profile.update`, `teacher.logout`). Avoid naming a controller method `verifyForm` because Wayfinder generates an internal `verifyForm` helper for `verify.form` and TypeScript declarations collide. `App\Models\Core\User::hasVerifiedEmail()` override returns `true` for `Teacher` (bypasses `verified` middleware; `Teacher` guard is `auth,verified,teacher.profile.completed,role:Teacher`). `PenyaluranService::me()` caches `penyaluran:me:`.sha1(token) (sha1 fix for token-safe cache key, 300s TTL). `PenyaluranService::updateMe()` `PUT guru/me` invalidates cache. Inertia views in `FortifyServiceProvider`. **Unified Socialite OAuth** in `routes/auth.php` (`auth/{provider}/redirect` & `auth/{provider}/callback` single callback endpoint across all personas): strict check requires email already registered in DB (unregistered shows flash toast error `Akun dengan email {email} belum terdaftar. Silakan daftarkan akun Anda terlebih dahulu saat periode pendaftaran dibuka.`); guru Google login allowed only if `Teacher` profile completed (`!needsTeacherProfileCompletion()`), else blocked with flash error; on success smart redirect to `teacher.dashboard` for Teacher, `student.dashboard` for Participant, `admin.dashboard` for Administrators. Breadcrumbs for `teacher.login`, `teacher.verify`, and `teacher.profile.edit` live in `routes/breadcrumbs/auth-breadcrumbs.php`; `HandleInertiaRequests::share()` wraps `Breadcrumbs::generate` in try-catch -> `[]` if missing.
- **Routing**: `routes/web.php` only requires the others: `auth.php`, `settings.php`, `admin.php`, `teacher.php`, `student.php`, `home.php`. Controllers split by namespace (`App\Http\Controllers\Admin`, `Home`, `Auth`, `Settings`, `Teacher`, `Student`, `Company`) matching route files. Admin Chaperones routes at `/admin/companies/chaperones` (`admin.companies.chaperones.*` resource + `data` + `card` + `verify` + `teacher-detail`), public chaperone verification at `/verifikasi/pendamping/{code}` (`home.chaperone.verify`). Teacher portal routes are at `/teacher/*` (`routes/teacher.php`, prefix `teacher` as `teacher.`): `dashboard` (`teacher.dashboard`), `biodata` (`teacher.biodata.*`), `data-peserta` (`teacher.data-peserta.*` resource `only index,create,store,show,destroy` + `data` + `card`), `data-binaan` (`teacher.data-binaan.*` resource `binaan`), `data-sanggar` (`teacher.data-sanggar.*` read-only), `absensi` (`teacher.absensi.index`). Auth teacher routes at `/teacher/*` (`teacher.login`, `teacher.verify`, `teacher.profile.edit/update`, `teacher.logout`). Socialite Google: single `auth/{provider}/redirect/callback` endpoint for all users. Settings routes use `as('admin.')` name-prefix (not URL prefix) under `auth` / `auth+verified` guards plus `teacher.profile.completed` - URLs are `/settings/profile`, `/settings/security` (names `admin.profile.edit`, etc.).

Uses Spatie roles/permissions. Roles: `Administrators` (global access), `Cabang` (branch-scoped access via `kantor_id` & `branch`), `Teacher`, `Participant`, `Users`. - **Participant Verification & Payment Lifecycle**:
  - `status` values: `submitted` (menunggu verifikasi), `verified` (terverifikasi), `rejected` (ditolak).

Pada user `Cabang`, kolom `status` disembunyikan untuk menghindari kebingungan antara status verifikasi dan status pembayaran (Cabang hanya fokus pada konfirmasi pembayaran dan data cabang).

- **Payment Proof & Document Upload / Re-Upload Rules**:
  - Trait `UploadFiles::uploadFile(?string $oldPath, UploadedFile $file, string $folder, string $disk = 'public')` **wajib** menerima 4 parameter dengan `$oldPath` sebagai argumen ke-1 dan `UploadedFile $file` sebagai argumen ke-2. Jangan pernah melewatkan `$oldPath` karena akan menyebabkan fatal error type mismatch. File lama di storage otomatis dihapus.
  - **Student Re-Upload Locking Rules**:
    - **Bukti Bayar (`payment_proof`)**: Endpoint `POST /student/payment-proof` (`ParticipantPaymentController@uploadProof`). Diizinkan mengunggah ulang jika status pendaftaran `rejected` atau status pembayaran `unpaid` / `waiting_confirmation`. **Dilarang/Terkunci** jika pembayaran sudah `paid` atau status peserta sudah `verified`. Jika pendaftaran sebelumnya `rejected`, unggah ulang mereset status ke `submitted` dan `payment_status` ke `waiting_confirmation`.
    - **Dokumen Identitas / Kartu Pelajar (`student_card`)**: Endpoint `POST /student/document` (`ParticipantPaymentController@uploadDocument`). Diizinkan mengunggah/mengganti dokumen selama status peserta belum `verified`. **Terkunci** saat status peserta `verified`. Jika sebelumnya `rejected`, unggah ulang mereset status ke `submitted` agar diverifikasi ulang oleh panitia.
  - **Document Preview via `ProofModal`**: Pada seluruh antarmuka peserta (form edit admin `participant-form.tsx`, detail peserta admin `admin/company/participant/show.tsx`, detail peserta guru `teacher/data-peserta/show.tsx`, dashboard peserta `participant.tsx`, maupun tabel list), file dokumen (`payment_proof` dan `student_card`) **wajib** menggunakan `ProofModal` (`resources/js/components/ui/proof-modal.tsx`) dengan fitur zoom, rotate, reset, scroll wheel zoom, download, dan viewer PDF/gambar (jangan gunakan tag anchor tautan biasa).
- **Dynamic Teacher & Sanggar Association**: Pada form edit peserta (`participant-form.tsx`), pilihan dropdown **Sanggar Binaan** secara dinamis difilter berdasarkan sanggar milik guru pembimbing yang dipilih (`teachers.find(...).sanggars`). Jika belum ada guru atau guru tidak memiliki sanggar spesifik, fallback ke daftar seluruh sanggar.
- **Participant Registration Concurrency & Anti-Collision Standards**:
  - **Soft-Deleted Safety with `withTrashed()`**: Penghitungan urutan nomor registrasi (`Participant::generateRegistrationNumber()`) **wajib** menggunakan `withTrashed()` agar record yang pernah dihapus tetap terhitung. Hal ini mencegah tabrakan pada `UNIQUE KEY participants_registration_number_unique` di tabel MySQL jika ada record lama yang di-soft delete.
  - **Atomic Distributed Lock**: Pembacaan sequence nomor dibungkus `Cache::lock("participant_reg_lock:{$prefix}", 10)->block(5)` sehingga dalam ribuan request per detik, pembuatan nomor terantre rapi tanpa bentrok.
  - **Optimistic Concurrency Auto-Retry**: Endpoint `ParticipantRegistrationController@store` dan `TeacherService@registerStudent` membungkus `Participant::create` dalam blok retry (maksimal 5 percobaan dengan exponential backoff `usleep`) saat menangkap `UniqueConstraintViolationException` / `QueryException` (error 1062 / 23000) sehingga pendaftaran pengguna tetap berhasil mulus tanpa pesan error 500.
  - **File I/O Decoupling**: Upload file ke storage disk fisik dilakukan di luar `DB::transaction` agar koneksi database tidak terkunci lama saat transfer file.
- **Server Load Safeguards & Cloudflare Error 525 Prevention**:
  - **Client-Side Image Compression**: File gambar upload (`payment_proof` dan `student_card`) dikompresi di browser pengguna via `resources/js/utils/image-compression.ts` menggunakan HTML5 Canvas menjadi format JPEG berkualitas optimal (maks 1600px, quality 0.8, target ~150KB - 350KB). Mengurangi ukuran transfer hingga >90%, memangkas waktu unggah di koneksi seluler HP secara drastis, dan mencegah worker PHP-FPM / web server kehabisan proses (`pm.max_children`) yang memicu Cloudflare Error 525 (SSL Handshake Failed).
  - **Targeted Penyaluran API Search**: Pengecekan NIK santri binaan di `StoreParticipantRequest` dan `checkSantriBinaanStatus` menggunakan parameter `['search' => $nik]`, bukan memuat pagination semua santri (`allStudents()`) secara sinkron yang dapat membekukan worker thread PHP.
- **Dynamic Multi-Admin WhatsApp Integration**:
  - Pengaturan kontak WhatsApp di `admin/settings/site` (`site-form.tsx`) menggunakan repeater dinamis (Opsi 1) yang menyimpan array kontak `[{ name, number }]` secara terstruktur dalam kolom `whatsapp` (JSON string).

## Standar Pengembangan Fitur (Feature Development Lifecycle)

Setiap pembuatan atau pembaruan fitur **wajib** mengikuti 3 tahap standar sebelum dideploy ke server produksi untuk mencegah bug dan kebocoran data:

### 1. Buat Fitur (Architecture & Scaffolding)
- **Routing & Controller**: Rute modular di `routes/{module}.php` dengan controller namespace terpisah (`Teacher`, `Admin`, `Auth`, `Home`).
- **Form Request & Services**: Validasi terisolasi di FormRequest (`App\Http\Requests\Company\*`) dan logika bisnis di Service Layer (`App\Services\*`).
- **Schema & Migrations**: Tidak membuat file migrasi baru untuk ubah skema — selalu edit file `create_*` yang sudah ada (dengan index kolom filter, FK, dan unique constraint).
- **Frontend SPA**: React 19 + Inertia v3 dengan Shadcn UI, Wayfinder routes type-safe, dan breadcrumbs `.layout` pada setiap halaman.

### 2. Fungsionalitas Fitur (Business Logic & Data Isolation)
- **Strict Data Isolation (Zero Leakage)**: Query data guru wajib dibatasi hanya pada data miliknya (`where('mentor_id', Auth::id())`), dilarang membocorkan data antar guru walau berada di sanggar yang sama.
- **Aturan Bisnis Tunggal (Single Source of Truth)**:
  - **1 NIK = 1 Olimpiade per `event_year`**: Cek NIK via `Student::hasActiveRegistrationFor($nik, $eventYear)` di semua jalur (Guru, Umum, Admin).
  - **Locked Binaan Flow**: Pendaftaran santri binaan guru wajib berasal dari Data Binaan (klik "Daftarkan"). Akses langsung ke `/teacher/data-peserta/create` tanpa santri wajib di-redirect ke Data Binaan. Form pendaftaran menampilkan field nama santri terpilih secara terkunci (*read-only* dengan ikon gembok) di atas pilihan Sanggar.
  - **Full-Stack NIK Validation**: Santri binaan wajib memiliki NIK valid dari Penyaluran (bukan kosong, `-`, `0`, `'null'`, atau `< 10 digit`). Jika tidak valid, tombol pendaftaran di-lock dengan *Amber Alert Banner* dan backend `StoreTeacherParticipantRequest` melempar error validasi.
  - **Auto-Verified & Auto-Paid (Jalur Guru Binaan)**: Pendaftaran melalui guru binaan otomatis diset `status = 'verified'`, `payment_status = 'paid'`, dan `payment_amount = 0` (gratis program binaan sanggar).
  - **Payment-to-Verification Auto Sync**: Pembayaran lunas (`payment_status = 'paid'`) oleh panitia/keuangan otomatis memvalidasi status peserta (`status = 'verified'`). Bila status pembayaran diturunkan kembali ke `unpaid`/`waiting_confirmation`, peserta non-binaan otomatis di-reset ke `submitted`.
  - **Rejection & Re-upload Loop**: Peserta berstatus `rejected` dapat mengunggah ulang bukti transfer baru via `/student/payment-proof` atau dokumen kartu pelajar via `/student/document`, yang otomatis memulihkan status pendaftaran ke `submitted`. Bila status pembayaran sudah `paid` atau pendaftaran `verified`, pengunggahan ulang dikunci secara ketat di backend dan UI.
  - **Interactive Document Modal Standard**: Seluruh dokumen pratinjau (`student_card_url` dan `payment_proof_url`) di halaman admin, guru, dan peserta wajib menggunakan `ProofModal` (termasuk tombol rotasi dan zoom) guna memastikan kenyamanan inspeksi berkas dan mencegah membuka file di tab terpisah.
  - **UploadFiles Trait Parameter Integrity**: Pemanggilan `uploadFile(?string $oldPath, UploadedFile $file, string $folder, string $disk = 'public')` **wajib** menyertakan `$oldPath` (atau `null` bila file baru) di argumen ke-1. Dilarang melewatkan argumen `$oldPath` karena menyebabkan runtime type error.
  - **Two-Way Synchronization**: `StudentService::resolveFromPenyaluran` (inbound saat buka form edit) & `StudentService::syncToPenyaluran` (outbound saat simpan form) menjaga data santri di OMATIQ dan Penyaluran selalu identik.
- **Atomic Operations & Concurrency**: Multi-step write wajib dibungkus `DB::transaction()`, dan nomor registrasi memakai `lockForUpdate()`.

### 3. Optimasi Fitur (Performance, Scale & Pre-Deploy Quality Gates)
- **Query Optimization & N+1 Prevention**: Wajib `with()` kolom spesifik (`olimpiade:id,name`, `student:id,full_name,nik`), bounded pagination (`perPage <= 100`), dan hindari `->get()` tanpa limit.
- **Pest Automated Tests**: Setiap fitur wajib disertai test case di `tests/Feature/` mencakup:
  - *Positive happy path*
  - *Data isolation* antar user/role
  - *Duplicate constraint* (NIK/tahun event ganda)
  - *Direct URL access/tampering protection*
- **Pre-Deployment Quality Checklist**:
  1. `npm run lint:check` (ESLint)
  2. `npm run format:check` (Prettier)
  3. `npm run types:check` (TypeScript `tsc --noEmit` — 0 errors)
  4. `vendor/bin/pint --dirty --format agent` (PHP formatting)
  5. `composer run test` / `php artisan test --compact` (100% tests passed)

## Data Management & Scale

Target: tables will grow to thousands+ rows. Optimize for that from day one.

- **Eager loading & N+1**: always `with()` relations in list/datatable queries; never lazy-load inside loops. Use explicit column lists (`->get(['id', 'name'])`) in eager loads to keep payloads small.
- **Inertia payloads**: never rely on Eloquent `$hidden`/`$visible` when building page props — they silently strip columns during serialization (Region models hide `province_id`/`regency_id`/`district_id`). If a hidden column is needed on the client, map the query to plain arrays (`->map(fn ($m) => ['id' => $m->id, ...])`); don't call `makeVisible()` ad hoc. Send only columns the page actually renders.
- **Reference lists (cascading dropdowns)**: don't ship the full region table to every page. If a parent→child lookup (province→regency) grows large, serve it from a dedicated endpoint filtered by parent id instead of filtering a full `regencies` prop client-side.
- **Indexes**: edit the `create_*` migration (schema changes never get new migration files). Index every column used in `where`, `orderBy`, `join`, and FK lookups — e.g. on `participants`: `status`, `[mentor_id, created_at]`, `created_at`, `registration_number` (unique), `penyaluran_sanggar_id` (index), `event_year` (index); `student_id`/`olimpiade_id`/`user_id`/`mentor_id` via FK, `students` retains `SoftDeletes` + indexes `province_id,regency_id,district_id,village_id,penyaluran_id,school_name,is_binaan,is_active,[mentor_id,created_at]` and `unique(nik,deleted_at)` — **do not add `deleted_at` to `participants`** (hard delete).
- **Soft-delete-aware unique constraints**: a trashed row still occupies its unique value (e.g. `students.nik` `unique(nik,deleted_at)`). If the same NIK must be re-registerable after soft-delete, use composite unique on `(nik, deleted_at)` (as `students` does). `participants` is **hard delete** (no `deleted_at`, no `SoftDeletes`) — `registration_number` remains plain `unique`, `nik` is nullable non-unique for public compatibility, and no `penyaluran_student_*` snapshot columns belong in `participants`; re-registering same binaan is blocked by application logic `whereIn(status,[submitted,verified])` + `event_year` not DB unique (see `TeacherService::getFormOptionsFromApi` + `StoreTeacherParticipantRequest`); 2026 `nik` terdaftar tidak bisa daftar lagi di 2026, tapi bisa di 2027 (buat `Olimpiade` `event_year=2027`).
- **LIKE searches**: `LIKE '%term%'` (used by `globalSearch`) is a full scan. Prefix `LIKE 'term%'` can use an index; at scale switch to full-text search.
- **Admin participant filters**: list peserta admin (`ParticipantController@getData` + `resources/js/pages/admin/company/participant/list.tsx`) must keep operational filters server-side and paginated: `olimpiade_id`, `status`, `registration_type`, `event_year`, `payment_status`, and `branch` plus GSheet realtime (1 sheet auto header `No|Registrasi|NIK...`, `upsertByRegNo`, `queue:work`). Do not fetch all participants into React for filtering/export; add indexes in the original `create_participants_table` migration for any new filter columns.
- **Pagination, always**: never `->get()` on an unbounded result set. `getData()` must default to a bounded `perPage` (no `get()` fallback) and cap it (current cap = 100). For very large tables prefer `cursorPaginate`.
- **Batch jobs**: use `chunkById`/`cursor()`/`lazy()` for any batch processing (sync, export, backup) — never `->get()` everything. `sheets:sync` uses `chunkById(200)`.
- **Delete semantics**: deleting a child record (e.g. Participant) must never delete parent master data (Student) or its media files just because it references them. Wrap multi-step writes in `DB::transaction` and keep sequence generation under `lockForUpdate` (see `generateRegistrationNumber()` — uses `max()` + `lockForUpdate`, no `deleted_at` — run `migrate:fresh --seed` after hardness change or DB GUI shows 1054).
- **Activity logging**: `LogsActivity` fires per model event; keep `logOnlyDirty()`, avoid row-by-row logging inside bulk operations.
