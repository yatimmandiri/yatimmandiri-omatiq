# AGENTS.md — Yatim Mandiri OmatiQ

## Stack

Laravel 13 + Inertia v3 + React 19 SPA. TypeScript 6, Tailwind v4, Vite 8.

## Architecture

- **Auth**: Fortify handles login/register/reset-password/2FA/email-verification (for `Administrators`/`Participant`). Guru login is **phone + local password via Penyaluran identity** (`GuruAuthController@store` validates `phone` + `password` -> `POST api/v1/guru/login` `{phone}` -> Bearer token -> `GET guru/me` -> `User::firstOrCreate(penyaluran_id)` with local placeholder email `guru{id}@penyaluran.local`, synced `penyaluran_token`/`phone`/`Teacher` role, and default first password `password` until admin-provided/reset). After successful password check, first-time/incomplete teachers are forced to `GET guru/complete-profile` (`auth/guru-complete-profile.tsx`) via `User::needsTeacherProfileCompletion()` (`Teacher` role + `teacher_profile_completed_at` null + placeholder email), then `PUT guru/complete-profile` validates `email` (unique, lowercase) + `password` (`Password::min(8)` explicit, global `Password::defaults()` = `Password::min(8)` always via `AppServiceProvider` production+local) → `PenyaluranService::updateMe(token)` `PUT api/v1/guru/me` `{email}` Bearer (timeout 8, retry 2, `Cache::forget penyaluran:me:`.sha1(token)) — if API fails local DB is **not** updated and `withErrors('email')` is returned (best practice: token missing → `Sesi Penyaluran tidak ditemukan`); on success it stores real unique email, hashes new password, sets `email_verified_at` + `teacher_profile_completed_at`, and redirects to `admin.dashboard`; completed teachers skip this form on future logins. `EnsureTeacherProfileCompleted` middleware protects admin/settings areas from bypassing the required profile completion page. Direct `Auth::login` is used when `PENYALURAN_OTP_ENABLED=false` (default, `config/services.php:penyaluran.otp_enabled`). **OTP scaffold** (`app/Services/PhoneOtpService.php`, hashed 6-digit `phone_otp` + `phone_otp_expires_at` 5min / `phone_otp_attempts` 5 / lockout 15min / resend cooldown 60s, `users.phone_otp*` + `phone_verified_at` columns) when `PENYALURAN_OTP_ENABLED=true`: `generate()` -> `session otp_user_id` -> `GET guru/verify-otp` (`GuruAuthController@showOtpForm`, `auth/guru-verify-otp.tsx`) -> `POST guru/verify-otp` -> `POST guru/resend-otp`; routes under `guest` + throttles `5,1`/`3,1` in `routes/auth.php` (`guru.login`, `guru.login.store`, `guru.verify`, `guru.verify.store`, `guru.resend`, `guru.profile.edit`, `guru.profile.update`, `guru.logout`). Avoid naming a controller method `verifyForm` because Wayfinder generates an internal `verifyForm` helper for `verify.form` and TypeScript declarations collide. `App\Models\Core\User::hasVerifiedEmail()` override returns `true` for `Teacher` (bypasses `verified` middleware; `Admin` guard is `auth,verified,auth.admin,guru.profile.completed`). `PenyaluranService::me()` caches `penyaluran:me:`.sha1(token) (sha1 fix for token-safe cache key, 300s TTL). `PenyaluranService::updateMe()` `PUT guru/me` invalidates cache. Inertia views in `FortifyServiceProvider`. Socialite OAuth in `routes/auth.php`; future Google login for teachers should bind to the completed real email, not the `@penyaluran.local` placeholder. `routes/admin.php` only wires `AuthController@updateProfile`; remaining methods dead. Breadcrumbs for `guru.login`, `guru.verify`, and `guru.profile.edit` live in `routes/breadcrumbs/auth-breadcrumbs.php`; `HandleInertiaRequests::share()` wraps `Breadcrumbs::generate` in try-catch -> `[]` if missing.
- **Routing**: `routes/web.php` only requires the others: `auth.php`, `settings.php`, `admin.php`, `home.php`. Controllers split by namespace (`App\Http\Controllers\Admin`, `Home`, `Auth`, `Settings` + `Admin\Settings` for `SiteSettingsController` + `Admin\Guru` for `DataPesertaController/BinaanController/SanggarController/AbsensiController`) matching route files. Guru admin routes are at `/admin/guru/*` (prefix `guru` as `guru.`), not `/admin/teacher/*` (old URL now 404): `data-peserta` (`admin.guru.data-peserta.*` resource `only index,create,store,show` + `data`), `data-binaan` (`admin.guru.data-binaan.*` resource `binaan`), `data-sanggar` (`admin.guru.data-sanggar.*` read-only), `absensi` (`admin.guru.absensi.index`). Auth guru routes at `/guru/*` (`guru.login`, `guru.verify`, `guru.profile.edit/update`, `guru.logout`). Settings routes use `as('admin.')` name-prefix (not URL prefix) under `auth` / `auth+verified` guards plus `guru.profile.completed` - URLs are `/settings/profile`, `/settings/security` (names `admin.profile.edit`, etc.).
- **Admin**: All admin routes at `/admin/*`, guarded by `auth`, `verified`, `auth.admin`, `guru.profile.completed` (`App\Http\Middleware\AdminMiddleware`, `App\Http\Middleware\EnsureTeacherProfileCompleted`). Uses Spatie roles/permissions. Middleware aliases defined in `bootstrap/app.php`: `auth.admin`, `auth.user` (`UserMiddleware` - no-op passthrough), `guru.profile.completed` (also `teacher.profile.completed` alias kept for BC, redirects incomplete Teacher users to `guru.profile.edit`), `guest.redirect` (`RedirectIfAuthenticated`), plus Spatie `role` / `permission` / `role_or_permission`. `AdminMiddleware` is a **blacklist**, not a whitelist - it 403s anyone with `Users` role unless they also have `Participant` or `Teacher` (so `Users+Administrators` would also 403 - avoid assigning `Users` alongside `Administrators`); it never checks for an admin role. Roles seeded in `UserRolePermissionSeeder`: `Administrators` (all permissions), `Teacher` (view/create/data-participant), `Participant` (view/data-participant), `Users` (default, no permissions). `config/permission.php` maps to the base `Spatie\Permission\Models` Role/Permission, so `App\Models\Core\Role` / `Core\Permission` are wrappers not wired via config (but used in the seeder - don't delete them). **Data Guru** (`Admin\Company\TeacherController`) is read-only — routes `only(['index','show'])` + `getData` + `resetPassword`; `create/store/edit/update/destroy` `abort(403)`; data guru snapshot from Penyaluran on login; list shows only `Detail` (outline) hide `Edit/Delete`.
- **Public**: Public routes in `routes/home.php` — home page, about, olimpiade listing, schedule, registration, news, contact. Registration public uses `Olimpiade::active()->ordered()` (all `status=true`, no `show_on_registration` filter — `show_on_registration` column removed 2026-09-02).
- **Layouts**: Selected in `resources/js/app.tsx` by page name prefix: `home/*` → HomeLayout, `auth/*` → AuthLayout, `settings/*` → [AppLayout, SettingsLayout], `welcome` → null, default → AppLayout.
- **Route types**: Use Wayfinder generated imports — `@/routes/` for named routes, `@/actions/` for controller actions. Regenerate when routes change via the Vite plugin / `wayfinder:generate` if TS errors appear.
- **Sheets**: `config/sheets.php` + `SiteSettings sheets_sync_enabled/spreadsheet_id/sheet_name` + `GoogleSheetService` (`google/apiclient` Service Account `storage/app/google/credentials.json` via `GSHEETS_CREDENTIALS`, `HEADERS` 20 cols `No|Registrasi|NIK|NIS|Nama...Tgl Daftar`, `ensureHeaderRow`, `upsertByRegNo`, `batchUpsert`), `SyncParticipantToSheet` job `ShouldQueue tries 3 backoff 30,60 afterCommit`, `ParticipantObserver` (`created/updated/deleted` dispatch job, skip `migrate:fresh --seed` & `testing`), `sheets:sync` command `chunkById(200)`, admin `ParticipantController@index` provides `sheets {enabled,spreadsheet_id,url}` prop, `list.tsx` shows `Live/Off` + `Buka GSheet` (public Viewer, NIK full) + `Sync Ulang` `POST participants/sync-sheet` `admin.companies.participants.sync-sheet` (`ParticipantPolicy@syncSheet` admin only `update-participant`). Queue `database` (`QUEUE_CONNECTION=database`).

## Conventions

- **Migrations**: Do NOT create separate migration files for schema changes. Always edit the existing `create_*` table migration directly, since we use `migrate:fresh --seed`. This applies to every feature — modify the original table creation file, not a new `update_*` file. Exception for production with existing data: create incremental `2026_09_02_*` migrations with `hasColumn/hasTable` checks and `exists` checks for `SiteSettings` (`migrator->exists`).
- Use `php artisan make:*` with `--no-interaction` for all new files.
- New models should ship with factories and seeders.
- Controllers use Admin/Home/Settings namespace split matching route files. Guru admin uses `Admin\Guru` namespace (`DataPesertaController`, `BinaanController`, `SanggarController`, `AbsensiController`) for `/admin/guru/*` routes. Beware: `App\Http\Controllers\SliderController` and `App\Http\Controllers\FaqCompanyController` are unused leftovers at `app/Http/Controllers/SliderController.php` / `FaqCompanyController.php` with wrong namespace `Admin\Company` (PSR-4 mismatch) — always use the `Admin\Company\*` versions.
- **UI label "Binaan"**: the Student concept is shown to users as **"Binaan"** everywhere in the UI — sidebar (`Kelola Binaan` only; `Data Binaan` removed), page headings (`Detail Binaan`, `Daftarkan Binaan`), breadcrumbs, table headers, flash messages (`Binaan {name} berhasil ditambahkan.`) and validation errors (`Binaan ini bukan binaan Anda.`). Never show "Siswa"/"Murid" in user-facing strings. The DB schema and code identifiers keep `student*` (`Student`, `students`, `student_id`) — do not rename them to match the label. `routes/breadcrumbs/*` labels use "Binaan" too. Admin `Participant` edit (`ParticipantController@edit/update` + `UpdateParticipantRequest`) can edit **all** `students` fields via the `student` relation (binaan `isBinaan` fields `nik,nis,full_name,gender,school_level,school,birth_date,address,province/regency/district/village` sync to `students`; no `age` field); admin can edit **all** `participants` plus **inline verification** in list. Guru via `DataPesertaController@store` uses a minimal form (`binaan`, `sanggar`, `olimpiade`, optional `achievements/notes`) and fills `Student` master from Penyaluran (`penyaluran_id` + `nik,nis,full_name,nickname,gender,school_level,school,grade,birth_place,birth_date,address,parent_phone,mentor_id,mentor_name,mentor_phone,is_binaan=true`) + `Participant` form (`student_id, penyaluran_sanggar_id/name, olimpiade_id, event_year, achievements,has_joined_before,previous_year,referral_source,branch,notes,status=verified`).
- Regions (province/regency/district/village) use `azishapidin/indoregion`.
- Site settings via `spatie/laravel-settings` — see `app/Settings/SiteSettings.php` (`registration_public_open`, `registration_binaan_open`, `sheets_sync_enabled`, `sheets_spreadsheet_id`, `sheets_sheet_name`).
- Breadcrumbs via `diglactic/laravel-breadcrumbs` — `routes/breadcrumbs.php` for Blade (requires per-area files in `routes/breadcrumbs/`); every Inertia page component **must** define a static `.layout` property with `breadcrumbs` array: `{ title: string, href: routeHelper().url }`. Last item = current page (plain text). Import `dashboard` from `@/routes/admin` for the root breadcrumb. Guru breadcrumbs in `routes/breadcrumbs/admin/guru-breadcrumbs.php` (old `teacher-breadcrumbs` removed, 404 for `/admin/teacher/*`).
- **New routes**: every new page/route (public `routes/home.php`, `routes/settings.php`, `routes/admin.php`) must add its own page component with a `.layout` breadcrumbs array — this is how the current page shows in the AppLayout header. ## Data Management & Scale

Target: tables will grow to thousands+ rows. Optimize for that from day one.

- **Eager loading & N+1**: always `with()` relations in list/datatable queries; never lazy-load inside loops. Use explicit column lists (`->get(['id', 'name'])`) in eager loads to keep payloads small.
- **Inertia payloads**: never rely on Eloquent `$hidden`/`$visible` when building page props — they silently strip columns during serialization (Region models hide `province_id`/`regency_id`/`district_id`). If a hidden column is needed on the client, map the query to plain arrays (`->map(fn ($m) => ['id' => $m->id, ...])`); don't call `makeVisible()` ad hoc. Send only columns the page actually renders.
- **Reference lists (cascading dropdowns)**: don't ship the full region table to every page. If a parent→child lookup (province→regency) grows large, serve it from a dedicated endpoint filtered by parent id instead of filtering a full `regencies` prop client-side.
- **Indexes**: edit the `create_*` migration (schema changes never get new migration files). Index every column used in `where`, `orderBy`, `join`, and FK lookups — e.g. on `participants`: `status`, `[mentor_id, created_at]`, `created_at`, `registration_number` (unique), `penyaluran_sanggar_id` (index), `event_year` (index); `student_id`/`olimpiade_id`/`user_id`/`mentor_id` via FK, `students` retains `SoftDeletes` + indexes `province_id,regency_id,district_id,village_id,penyaluran_id,school_name,is_binaan,[mentor_id,created_at]` and `unique(nik,deleted_at)` — **do not add `deleted_at` to `participants`** (hard delete).
- **Soft-delete-aware unique constraints**: a trashed row still occupies its unique value (e.g. `students.nik` `unique(nik,deleted_at)`). If the same NIK must be re-registerable after soft-delete, use composite unique on `(nik, deleted_at)` (as `students` does). `participants` is **hard delete** (no `deleted_at`, no `SoftDeletes`) — `registration_number` remains plain `unique`, `nik` is nullable non-unique for public compatibility, and no `penyaluran_student_*` snapshot columns belong in `participants`; re-registering same binaan is blocked by application logic `whereIn(status,[submitted,verified])` + `event_year` not DB unique (see `TeacherService::getFormOptionsFromApi` + `StoreTeacherParticipantRequest`); 2026 `nik` terdaftar tidak bisa daftar lagi di 2026, tapi bisa di 2027 (buat `Olimpiade` `event_year=2027`).
- **LIKE searches**: `LIKE '%term%'` (used by `globalSearch`) is a full scan. Prefix `LIKE 'term%'` can use an index; at scale switch to full-text search.
- **Admin participant filters**: list peserta admin (`ParticipantController@getData` + `resources/js/pages/admin/company/participant/list.tsx`) must keep operational filters server-side and paginated: `olimpiade_id`, `status`, `registration_type`, `event_year`, `payment_status`, and `branch` plus GSheet realtime (1 sheet auto header `No|Registrasi|NIK...`, `upsertByRegNo`, `queue:work`). Do not fetch all participants into React for filtering/export; add indexes in the original `create_participants_table` migration for any new filter columns.
- **Pagination, always**: never `->get()` on an unbounded result set. `getData()` must default to a bounded `perPage` (no `get()` fallback) and cap it (current cap = 100). For very large tables prefer `cursorPaginate`.
- **Batch jobs**: use `chunkById`/`cursor()`/`lazy()` for any batch processing (sync, export, backup) — never `->get()` everything. `sheets:sync` uses `chunkById(200)`.
- **Delete semantics**: deleting a child record (e.g. Participant) must never delete parent master data (Student) or its media files just because it references them. Wrap multi-step writes in `DB::transaction` and keep sequence generation under `lockForUpdate` (see `generateRegistrationNumber()` — uses `max()` + `lockForUpdate`, no `deleted_at` — run `migrate:fresh --seed` after hardness change or DB GUI shows 1054).
- **Activity logging**: `LogsActivity` fires per model event; keep `logOnlyDirty()`, avoid row-by-row logging inside bulk operations.

## Testing

- Pest v4, tests in `tests/Feature/` and `tests/Unit/`.
- PHPUnit config uses SQLite in-memory. Local PHP must have `pdo_sqlite`/`sqlite3` enabled; `spatie/laravel-backup` also requires ext-zip / `ZipArchive` for Laravel boot. Tests must not rely on external services.
- `RefreshDatabase` is **not** applied by default in `Pest.php` — apply per-testcase when needed.
- Factories live in `database/factories/` under PSR-4 `Database\Factories\`.
