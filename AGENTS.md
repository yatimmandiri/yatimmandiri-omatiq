# AGENTS.md — Yatim Mandiri OmatiQ

## Stack

Laravel 13 + Inertia v3 + React 19 SPA. TypeScript 6, Tailwind v4, Vite 8.

Key packages: Fortify (auth), Socialite, Reverb (websockets), Spatie (permissions, media-library, settings, activitylog, backup), Firebase, DomPDF, TipTap (rich text), Wayfinder (TS route helpers), Pest 4 (tests), google/apiclient (Sheets).

## Architecture

- **Auth**: Fortify handles login/register/reset-password/2FA/email-verification (for `Administrators`/`Participant`). Guru login is **phone + local password via Penyaluran identity** (`GuruAuthController@store` validates `phone` + `password` -> `POST api/v1/guru/login` `{phone}` -> Bearer token -> `GET guru/me` -> `User::firstOrCreate(penyaluran_id)` with local placeholder email `guru{id}@penyaluran.local`, synced `penyaluran_token`/`phone`/`Teacher` role, and default first password `password` until admin-provided/reset). After successful password check, first-time/incomplete teachers are forced to `GET teacher/complete-profile` (`auth/guru-complete-profile.tsx`) via `User::needsTeacherProfileCompletion()` (`Teacher` role + `teacher_profile_completed_at` null + placeholder email), then `PUT teacher/complete-profile` validates `email` (unique, lowercase) + `password` (`Password::min(8)` explicit, global `Password::defaults()` = `Password::min(8)` always via `AppServiceProvider` production+local) → `PenyaluranService::updateMe(token)` `PUT api/v1/guru/me` `{email}` Bearer (timeout 8, retry 2, `Cache::forget penyaluran:me:`.sha1(token)) — if API fails local DB is **not** updated and `withErrors('email')` is returned (best practice: token missing → `Sesi Penyaluran tidak ditemukan`); on success it stores real unique email, hashes new password, sets `email_verified_at` + `teacher_profile_completed_at`, and redirects to `teacher.dashboard`; completed teachers skip this form on future logins. `EnsureTeacherProfileCompleted` middleware protects admin/settings areas from bypassing the required profile completion page. Direct `Auth::login` is used when `PENYALURAN_OTP_ENABLED=false` (default, `config/services.php:penyaluran.otp_enabled`). `FortifyServiceProvider` binds `LoginResponse` and `LogoutResponse` role-aware (`Teacher` → `teacher.dashboard` / `teacher.login`, `Participant` → `student.dashboard` / `login`, `Administrators` → `admin.dashboard` / `admin.login`). `bootstrap/app.php` `Authenticate::redirectUsing` stores `url.intended` for `admin/*` → `login` vs `teacher/*` → `teacher.login` so `redirect()->intended` resumes last page, not `/`. `AuthController@loginStore` fallback `intended(admin.dashboard)` not `/`. **OTP scaffold** (`app/Services/PhoneOtpService.php`, hashed 6-digit `phone_otp` + `phone_otp_expires_at` 5min / `phone_otp_attempts` 5 / lockout 15min / resend cooldown 60s, `users.phone_otp*` + `phone_verified_at` columns) when `PENYALURAN_OTP_ENABLED=true`: `generate()` -> `session otp_user_id` -> `GET teacher/verify-otp` (`GuruAuthController@showOtpForm`, `auth/guru-verify-otp.tsx`) -> `POST teacher/verify-otp` -> `POST teacher/resend-otp`; routes under `guest` + throttles `5,1`/`3,1` in `routes/auth.php` (`teacher.login`, `teacher.login.store`, `teacher.verify`, `teacher.verify.store`, `teacher.resend`, `teacher.profile.edit`, `teacher.profile.update`, `teacher.logout`). Avoid naming a controller method `verifyForm` because Wayfinder generates an internal `verifyForm` helper for `verify.form` and TypeScript declarations collide. `App\Models\Core\User::hasVerifiedEmail()` override returns `true` for `Teacher` (bypasses `verified` middleware; `Teacher` guard is `auth,verified,teacher.profile.completed,role:Teacher`). `PenyaluranService::me()` caches `penyaluran:me:`.sha1(token) (sha1 fix for token-safe cache key, 300s TTL). `PenyaluranService::updateMe()` `PUT guru/me` invalidates cache. Inertia views in `FortifyServiceProvider`. **Unified Socialite OAuth** in `routes/auth.php` (`auth/{provider}/redirect` & `auth/{provider}/callback` single callback endpoint across all personas): strict check requires email already registered in DB (unregistered shows flash toast error `Akun dengan email {email} belum terdaftar. Silakan daftarkan akun Anda terlebih dahulu saat periode pendaftaran dibuka.`); guru Google login allowed only if `Teacher` profile completed (`!needsTeacherProfileCompletion()`), else blocked with flash error; on success smart redirect to `teacher.dashboard` for Teacher, `student.dashboard` for Participant, `admin.dashboard` for Administrators. Breadcrumbs for `teacher.login`, `teacher.verify`, and `teacher.profile.edit` live in `routes/breadcrumbs/auth-breadcrumbs.php`; `HandleInertiaRequests::share()` wraps `Breadcrumbs::generate` in try-catch -> `[]` if missing.
- **Routing**: `routes/web.php` only requires the others: `auth.php`, `settings.php`, `admin.php`, `teacher.php`, `student.php`, `home.php`. Controllers split by namespace (`App\Http\Controllers\Admin`, `Home`, `Auth`, `Settings`, `Teacher`, `Student`, `Company`) matching route files. Teacher portal routes are at `/teacher/*` (`routes/teacher.php`, prefix `teacher` as `teacher.`): `dashboard` (`teacher.dashboard`), `biodata` (`teacher.biodata.*`), `data-peserta` (`teacher.data-peserta.*` resource `only index,create,store,show,destroy` + `data` + `card`), `data-binaan` (`teacher.data-binaan.*` resource `binaan`), `data-sanggar` (`teacher.data-sanggar.*` read-only), `absensi` (`teacher.absensi.index`). Auth teacher routes at `/teacher/*` (`teacher.login`, `teacher.verify`, `teacher.profile.edit/update`, `teacher.logout`). Socialite Google: single `auth/{provider}/redirect/callback` endpoint for all users. Settings routes use `as('admin.')` name-prefix (not URL prefix) under `auth` / `auth+verified` guards plus `teacher.profile.completed` - URLs are `/settings/profile`, `/settings/security` (names `admin.profile.edit`, etc.).
- **Admin**: All admin routes at `/admin/*`, guarded by `auth`, `verified`, `auth.admin`, `guru.profile.completed` (`App\Http\Middleware\AdminMiddleware`, `App\Http\Middleware\EnsureTeacherProfileCompleted`). Uses Spatie roles/permissions. Middleware aliases defined in `bootstrap/app.php`: `auth.admin`, `auth.user` (`UserMiddleware` - no-op passthrough), `guru.profile.completed` (also `teacher.profile.completed` alias kept for BC, redirects incomplete Teacher users to `teacher.profile.edit`), `guest.redirect` (`RedirectIfAuthenticated`), plus Spatie `role` / `permission` / `role_or_permission`. `AdminMiddleware` is a **blacklist**, not a whitelist - it 403s anyone with `Users` role unless they also have `Participant` or `Teacher` (so `Users+Administrators` would also 403 - avoid assigning `Users` alongside `Administrators`); it never checks for an admin role. Roles seeded in `UserRolePermissionSeeder`: `Administrators` (all permissions), `Teacher` (view/create/data-participant), `Participant` (view/data-participant), `Users` (default, no permissions). `config/permission.php` maps to the base `Spatie\Permission\Models` Role/Permission, so `App\Models\Core\Role` / `Core\Permission` are wrappers not wired via config (but used in the seeder - don't delete them). **Data Guru** (`Admin\Company\TeacherController`) is read-only — routes `only(['index','show'])` + `getData` + `resetPassword`; `create/store/edit/update/destroy` `abort(403)`; data guru snapshot from Penyaluran on login; list shows only `Detail` (outline) hide `Edit/Delete`. **Data Students** (`Admin\Company\StudentController`) shows all `students` (binaan + umum) with `is_active` toggle `PUT students/{student}/status` + `is_binaan/is_active` server filters, `only(['index','show','edit','update','destroy'])` + `getData` (destroy protected if student has active participant registrations); **Unified Single Source of Truth**: on edit (`StudentController@edit`), resolves fresh snapshot from Penyaluran API via `StudentService::resolveFromPenyaluran()` for binaan, on update (`StudentController@update`) syncs two-way to Penyaluran remote API via `StudentService::syncToPenyaluran()` using the student's mentor token (for umum `penyaluran_id = null`, saved directly in local DB without calling Penyaluran); form in `admin/company/students/edit.tsx` uses Shadcn UI (`Select`, `Input`, `Textarea`, `Switch`, `Card`, `Label`, `Button`) with 4-level cascading wilayah (Provinsi -> Kabupaten/Kota -> Kecamatan -> Kelurahan/Desa) matching teacher portal; list `select|Aksi|No` sticky left, `Detail`, `Edit`, `Hapus` popup.
- **Attendance & Teaching Journal Hub (`Presensi & Jurnal Mengajar`)**: `Teacher\AbsensiController@index` (`routes/teacher.php:teacher.absensi.index`, `resources/js/pages/teacher/absensi/index.tsx`). 3-in-1 Attendance Hub for teachers: (1) Sanggar switcher with live summary cards (Total Pertemuan, Rata-rata Kehadiran %, Santri Terbina, Progres Modul); (2) Interactive Modal "Catat Presensi & Jurnal" with 1-click **"Tandai Semua Hadir"**, segmented attendance buttons per student (**H** Hadir `#10b981`, **S** Sakit `#f97316`, **I** Izin `#3b82f6`, **A** Alfa `#ef4444`), module topic & step/jilid inputs ready to consume Penyaluran curriculum API endpoints, individual student evaluation notes & session teaching journal notes, instant student search filter, and real-time attendance counter; (3) Timeline journal history tabs & aggregate student attendance summary.
- **Public**: Public routes in `routes/home.php` — home page, about, olimpiade listing, schedule, registration, news, contact, and participant card print `/pendaftaran/kartu/{registrationNumber}` (`home.registration.card`). Registration public uses `Olimpiade::active()->ordered()` (all `status=true`, no `show_on_registration` filter — `show_on_registration` column removed 2026-09-02).

## Domain

Two model namespaces:
- `App\Models\Core` — User, Role, Permission, Social, LogActivity; plus `App\Models\Core\Region` (Province, Regency, District, Village from `azishapidin/indoregion`)
- `App\Models\Company` — Olimpiade, OlimpiadeGallery, OlimpiadeObjective, OlimpiadeSchedule, OlimpiadeVideo, Participant, Student, Slider, Testimonial, Review, FaqCompany

Note: "Teacher" is **not** an Eloquent model — mentor/teacher roles are `User` rows with a Spatie role (`penyaluran_id`/`penyaluran_token`/`phone` synced from Penyaluran; `teacher_profile_completed_at` marks whether the teacher has replaced the placeholder email/password; `User::hasVerifiedEmail()` bypass for Teacher). `PenyaluranService` wraps `APP_PENYALURAN_URL` (`POST guru/login` `{phone}` → token → `GET guru/me` cached `penyaluran:me:`.sha1(token) returning full guru profile including nested `sanggars`, `students`, and `total_students` as the unified source of truth; `PUT guru/me` `{email}` Bearer (updateMe, Cache::forget); `students()` reads directly from `me(token)['students']` normalized to `{student_id,name,nickname,nik,nis,gender(P/L→male/female),school_name,school_level,class,birth_place,birth_date,address,guardian_name,guardian_phone,sanggar_id,sanggar_name,kantor_name,type,teacher_id,status}` de-duplicated by `student_id` with fallback to `guru/students`; for multi-sanggar teachers where santri lack explicit `sanggar_id` tags in API Penyaluran, `students($token, $sanggarId)` associates the santri to the requested sanggar if it is in the teacher's `sanggars`; `sanggars(string $token, bool $enrich = true)` supports `enrich: false` on fallback calls and `enrichSanggarsWithStudentCounts()` uses a static `$isEnrichingSanggars` recursion guard to prevent memory exhaustion; `PUT guru/students/{id}` `updateStudent()` synced on edit). `Teacher\DataPesertaController` is **participants table for guru** — `getData` is `Participant::where(mentor_id,Auth::id())->where(registration_type,teacher)` server-side `status/olimpiade_id/event_year` paginated `perPage≤100` via `search` + `participantPayload`, `index` provides `filterOptions olimpiades/eventYears`; `create/store/show` still Penyaluran API roster for pendaftaran (`students` fallback `testing` only), with automatic fallback lookup to all teacher students (`$penyaluran->students($token, null)`) if a student is not found in the sanggar-filtered roster; `destroy` cancels participant registration without deleting Student master data, `card` prints verified participant card. `Teacher\BinaanController` is pure API roster — `getData` from `PenyaluranService::students(token,sanggarId)` + `filterValue.sanggar_id/registration` + manual pagination cap 100, `TeacherService::getFormOptionsFromApi(eventYear)` excludes `where(event_year,eventYear)->whereIn(status,[submitted,verified])` via `students.penyaluran_id`/`student_id`, candidate matching between Penyaluran roster and local database is strictly NIK-based (rejects matches with conflicting NIKs to eliminate cross-teacher/cross-sanggar false "Terdaftar" status), `show(int $binaan)` is **API detail** `students()->firstWhere student_id==binaan` + `sanggars` map + `Participant` latest status, `edit` resolves fresh data via `resolveBinaan()` from Penyaluran and presents fully interactive form for all santri attributes (`full_name, nickname, nik, nis, gender, birth_place, birth_date, parent_phone, school_name, school_level, grade, address, province_id, regency_id, district_id, village_id`), `update` validates all fields (16-digit NIK unique per binaan, normalized gender, date before today) and syncs student updates to Penyaluran remote API via `PUT api/v1/guru/students/{id}` using `PenyaluranService::formatStudentPayload` before updating local `Student` and active `Participant` records, `registerStudent()` **creates or updates `Student` master** (`penyaluran_id` + `nik,nis,full_name,nickname,gender,school_level,school,grade,birth_place,birth_date,address,parent_phone,mentor_id,mentor_name,mentor_phone,is_binaan=true, user_id=null`) + `Participant` form (`student_id, penyaluran_sanggar_id/name, olimpiade_id, event_year, achievements,has_joined_before,previous_year,referral_source,branch,notes,status=verified,payment_status=paid,payment_amount=0`) — guru hanya wajib memilih `binaan`, `sanggar` (bila belum preselected), dan `olimpiade`; santri binaan wajib memiliki NIK valid dari Penyaluran (`nik` tidak boleh kosong), jika belum ada NIK maka tombol pendaftaran dinonaktifkan di `create.tsx` dengan banner peringatan dan divalidasi di `StoreTeacherParticipantRequest` / `DataPesertaController@store` mengarahkan guru melengkapi NIK terlebih dahulu di Penyaluran; detail binaan/kontak/cabang diambil dari Penyaluran (`guardian_phone`, `address`, `birth_date`, `kantor_name`) dan admin dapat melengkapi/mengoreksi setelah submit; pendaftaran dari guru otomatis `verified` dan `payment_status=paid` (gratis binaan) karena sumber binaan sudah dari Penyaluran, tetapi admin tetap bisa mengubah status; opsional guru isi `achievements` dan `notes` saja. `Teacher\SanggarController` read-only `sanggars` API. `Teacher\AbsensiController` attendance and teaching journal hub for assigned sanggars. Pendaftaran umum hanya mencatat `parent_phone` untuk kontak wali, tidak mengisi `mentor_name`/`mentor_phone`, dan status awalnya tetap `submitted` untuk verifikasi pembayaran admin. `is_binaan` **tanpa `users` row** (tryout nanti `students.user_id` nullable unique → `User` dibuat terpisah). `Student` is **master for both** umum & binaan (fields `nik,nis,full_name,gender,birth_date,school_level,school,grade,address,province/regency/district/village,penyaluran_id,user_id,parent_phone,mentor_id,mentor_name,mentor_phone,is_binaan,is_active`, no `age`), `SoftDeletes` + `unique(nik,deleted_at)` + indexes `penyaluran_id,district/village,is_active`); `participants` is **form murni hard delete** (`student_id, olimpiade_id, event_year, penyaluran_sanggar_id/name, mentor_id, user_id, registration_number, achievements, payment, consents, status`, no `penyaluran_student_*` snapshot — data binaan di `students`); `StudentController` (Data Binaan) removed — binaan via `students` master only. **1 NIK = 1 Olimpiade per `event_year`** (2026): cek NIK via `students.nik`/`participants.nik` + `event_year` + `whereIn(status,[submitted,verified])` di `Student::hasActiveRegistrationFor(nik,eventYear)` + `StoreTeacherParticipantRequest` + `StoreParticipantRequest`; contoh 2026 daftar MTK → 2026 tidak bisa daftar Al-Quran lagi, 2027 boleh daftar lagi (buat `Olimpiade` `event_year=2027` tanpa code change). `Olimpiade` `event_year` (year, default 2026, index) di `olimpiades` + `participants` (`event_year` index) via `create_*` edit; `OlimpiadeForm` input `event_year`; `show_on_registration` column removed 2026-09-02 (public now shows all `status=true`). Admin `Participant` (`ParticipantController@edit/update` with `StudentService` injected + `UpdateParticipantRequest`) is **unified single `Data Peserta` form** for both binaan & umum (binaan `isBinaan` fields `nik,nis,full_name,gender,school_level,school,birth_date,address,province/regency/district/village` sync to `students` & Penyaluran API via `StudentService::syncToPenyaluran`; no `age` field); admin can edit **all** `participants` plus **inline verification** in list (`PUT admin/companies/participants/{id}/status` `{status: submitted|verified|rejected}` via `Badge`+`DropdownMenu` in `list.tsx`) + **GSheet realtime** (1 sheet public Viewer, NIK full, `sheets_sync_enabled/spreadsheet_id/sheet_name` in `SiteSettings` + `config/sheets.php` `GSHEETS_*`, `GoogleSheetService` 20 headers `No|Registrasi|NIK|NIS|Nama...`, `SyncParticipantToSheet` queued `afterCommit`, `ParticipantObserver`, `sheets:sync` `chunkById`, `participants.sync-sheet` `ParticipantPolicy@syncSheet` admin only). `Admin\Company\TeacherController` (Data Guru) is read-only — routes `only(['index','show'])` + `getData`; `create/store/edit/update/destroy` `abort(403)`; data guru snapshot from Penyaluran on login; list shows only `Detail` (outline) hide `Edit/Delete`.

Unused scopes: `Testimonial::scopeType`, `Review::scopeType`, `FaqCompany::scopeSearch` are dead.

## Standar Pengembangan Fitur (Feature Development Lifecycle)

Setiap pembuatan atau pembaruan fitur **wajib** mengikuti 3 tahap standar sebelum dideploy ke server produksi untuk mencegah bug dan kebocoran data:

### 1. Buat Fitur (Architecture & Scaffolding)
- **Routing & Controller**: Rute modular di `routes/{module}.php` dengan controller namespace terpisah (`Teacher`, `Admin`, `Auth`, `Home`).
- **Form Request & Services**: Validasi terisolasi di FormRequest (`App\Http\Requests\Company\*`) dan logika bisnis di Service Layer (`App\Services\*`).
- **Schema & Migrations**: Tidak membuat file migrasi baru untuk ubah skema — selalu edit file `create_*` yang sudah ada (dengan index kolom filter, FK, dan unique constraint).
- **Frontend SPA**: React 19 + Inertia v3 dengan Shadcn UI, Wayfinder routes type-safe, dan breadcrumbs `.layout` pada setiap halaman.

### 2. Fungsionalitas Fitur (Business Logic & Data Isolation)
- **Strict Data Isolation (Zero Leakage)**: Query data guru wajib dibatasi hanya pada data miliknya (`where('mentor_id', Auth::id())`), dilarang membocorkan data antar guru walau berada di sanggar yang sama.
- **Aturan Bisnis Tunggal (Single Source of Truth)**:
  - **1 NIK = 1 Olimpiade per `event_year`**: Cek NIK via `Student::hasActiveRegistrationFor($nik, $eventYear)` di semua jalur (Guru, Umum, Admin).
  - **Locked Binaan Flow**: Pendaftaran santri binaan guru wajib berasal dari Data Binaan (klik "Daftarkan"). Akses langsung ke `/teacher/data-peserta/create` tanpa santri wajib di-redirect ke Data Binaan. Form pendaftaran menampilkan field nama santri terpilih secara terkunci (*read-only* dengan ikon gembok) di atas pilihan Sanggar.
  - **Full-Stack NIK Validation**: Santri binaan wajib memiliki NIK valid dari Penyaluran (bukan kosong, `-`, `0`, `'null'`, atau `< 10 digit`). Jika tidak valid, tombol pendaftaran di-lock dengan *Amber Alert Banner* dan backend `StoreTeacherParticipantRequest` melempar error validasi.
  - **Auto-Verified & Auto-Paid (Jalur Guru Binaan)**: Pendaftaran melalui guru binaan otomatis diset `status = 'verified'`, `payment_status = 'paid'`, dan `payment_amount = 0` (gratis program binaan sanggar).
  - **Two-Way Synchronization**: `StudentService::resolveFromPenyaluran` (inbound saat buka form edit) & `StudentService::syncToPenyaluran` (outbound saat simpan form) menjaga data santri di OMATIQ dan Penyaluran selalu identik.
- **Atomic Operations & Concurrency**: Multi-step write wajib dibungkus `DB::transaction()`, dan nomor registrasi memakai `lockForUpdate()`.

### 3. Optimasi Fitur (Performance, Scale & Pre-Deploy Quality Gates)
- **Query Optimization & N+1 Prevention**: Wajib `with()` kolom spesifik (`olimpiade:id,name`, `student:id,full_name,nik`), bounded pagination (`perPage <= 100`), dan hindari `->get()` tanpa limit.
- **Pest Automated Tests**: Setiap fitur wajib disertai test case di `tests/Feature/` mencakup:
  - *Positive happy path*
  - *Data isolation* antar user/role
  - *Duplicate constraint* (NIK/tahun event ganda)
  - *Direct URL access/tampering protection*
- **Pre-Deployment Quality Checklist**:
  1. `npm run lint:check` (ESLint)
  2. `npm run format:check` (Prettier)
  3. `npm run types:check` (TypeScript `tsc --noEmit` — 0 errors)
  4. `vendor/bin/pint --dirty --format agent` (PHP formatting)
  5. `composer run test` / `php artisan test --compact` (100% tests passed)

## Conventions

This applies to every feature — modify the original table creation file, not a new `update_*` file. Exception for production with existing data: create incremental `2026_09_02_*` migrations with `hasColumn/hasTable` checks and `exists` checks for `SiteSettings` (`migrator->exists`).

- New models should ship with factories and seeders.

## Data Management & Scale

Target: tables will grow to thousands+ rows. Optimize for that from day one.

- **Eager loading & N+1**: always `with()` relations in list/datatable queries; never lazy-load inside loops. Use explicit column lists (`->get(['id', 'name'])`) in eager loads to keep payloads small.
- **Inertia payloads**: never rely on Eloquent `$hidden`/`$visible` when building page props — they silently strip columns during serialization (Region models hide `province_id`/`regency_id`/`district_id`). If a hidden column is needed on the client, map the query to plain arrays (`->map(fn ($m) => ['id' => $m->id, ...])`); don't call `makeVisible()` ad hoc. Send only columns the page actually renders.
- **Reference lists (cascading dropdowns)**: don't ship the full region table to every page. If a parent→child lookup (province→regency) grows large, serve it from a dedicated endpoint filtered by parent id instead of filtering a full `regencies` prop client-side.
- **Indexes**: edit the `create_*` migration (schema changes never get new migration files). Index every column used in `where`, `orderBy`, `join`, and FK lookups — e.g. on `participants`: `status`, `[mentor_id, created_at]`, `created_at`, `registration_number` (unique), `penyaluran_sanggar_id` (index), `event_year` (index); `student_id`/`olimpiade_id`/`user_id`/`mentor_id` via FK, `students` retains `SoftDeletes` + indexes `province_id,regency_id,district_id,village_id,penyaluran_id,school_name,is_binaan,is_active,[mentor_id,created_at]` and `unique(nik,deleted_at)` — **do not add `deleted_at` to `participants`** (hard delete).
- **Soft-delete-aware unique constraints**: a trashed row still occupies its unique value (e.g. `students.nik` `unique(nik,deleted_at)`). If the same NIK must be re-registerable after soft-delete, use composite unique on `(nik, deleted_at)` (as `students` does). `participants` is **hard delete** (no `deleted_at`, no `SoftDeletes`) — `registration_number` remains plain `unique`, `nik` is nullable non-unique for public compatibility, and no `penyaluran_student_*` snapshot columns belong in `participants`; re-registering same binaan is blocked by application logic `whereIn(status,[submitted,verified])` + `event_year` not DB unique (see `TeacherService::getFormOptionsFromApi` + `StoreTeacherParticipantRequest`); 2026 `nik` terdaftar tidak bisa daftar lagi di 2026, tapi bisa di 2027 (buat `Olimpiade` `event_year=2027`).
- **LIKE searches**: `LIKE '%term%'` (used by `globalSearch`) is a full scan. Prefix `LIKE 'term%'` can use an index; at scale switch to full-text search.
- **Admin participant filters**: list peserta admin (`ParticipantController@getData` + `resources/js/pages/admin/company/participant/list.tsx`) must keep operational filters server-side and paginated: `olimpiade_id`, `status`, `registration_type`, `event_year`, `payment_status`, and `branch` plus GSheet realtime (1 sheet auto header `No|Registrasi|NIK...`, `upsertByRegNo`, `queue:work`). Do not fetch all participants into React for filtering/export; add indexes in the original `create_participants_table` migration for any new filter columns.
- **Pagination, always**: never `->get()` on an unbounded result set. `getData()` must default to a bounded `perPage` (no `get()` fallback) and cap it (current cap = 100). For very large tables prefer `cursorPaginate`.
- **Batch jobs**: use `chunkById`/`cursor()`/`lazy()` for any batch processing (sync, export, backup) — never `->get()` everything. `sheets:sync` uses `chunkById(200)`.
- **Delete semantics**: deleting a child record (e.g. Participant) must never delete parent master data (Student) or its media files just because it references them. Wrap multi-step writes in `DB::transaction` and keep sequence generation under `lockForUpdate` (see `generateRegistrationNumber()` — uses `max()` + `lockForUpdate`, no `deleted_at` — run `migrate:fresh --seed` after hardness change or DB GUI shows 1054).
- **Activity logging**: `LogsActivity` fires per model event; keep `logOnlyDirty()`, avoid row-by-row logging inside bulk operations.
